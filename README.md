# military-chess-online
Military chess strategy game: CPU play first, online multiplayer planned

日本の軍人将棋を基礎とする、スマートフォン優先の不完全情報型戦略ゲームです。**初回公開は1人用の対CPU戦**を目標とします。オンライン2人対戦は将来拡張として設計を保持します。

## 現状

対CPU戦、保存機能、スマートフォン向け配置・着手・履歴・結果表示を備えた、友人向けのテストプレイ版です。正式ルールはv0.2です。飛行機は前後移動で途中の敵味方駒を飛び越えます。保存形式と暗号化方式は変更していません。

初期配置・対局中とも三次元戦場と操作補助UIを中央に置き、十分な幅と高さがあれば左右にルールを並べます。1画面に収まらない画面ではルール欄を隠し、既存の「遊び方」から確認できます。

対局画面の正式な主操作面は三次元戦場です。自作低ポリゴン駒と常時名称ラベルを表示し、敵は終局まで共通外見に統一します。自軍→金枠の移動先→同じ目的地を再タップ、または補助UIの「確定して実行」で着手します。自軍駒を合法地点へドラッグしても着手でき、不合法なドロップでは盤面を変えません。HQ間飛行機はクリック方式ではC/D経路を先に選び、ドラッグでは目的HQのC側／D側へのドロップで選びます。選択解除・直前の着手／戦闘・履歴・終局後公開・保存再開も利用できます。Step 15では自由回転・ジェスチャー拡大を廃止し、視点を固定プリセットのボタンで切り替えます。「視点を戻す」で自軍側からの全景に戻ります。

Step 14では将官の金色の冠・外套、佐官の銀色の肩章、尉官の青色の徽章を使い、各階級群の上位から3/2/1本の装飾と身長差で区別します。特殊駒には翼、履帯、工具、馬、覆面、地雷装置、大きな旗を付け、名称も維持します。本陣の所属と占有駒の所属を分けて表示するため、自軍本陣へ敵が進入した場合も「敵軍 不明駒」と分かります。自軍駒は所在地点によらず名称を表示し、敵の正体は公開しません。HQ上の不明駒は「敵駒」、その他は「？」と表示します。PCの左右欄・上部帯とスマートフォンの余白を縮め、盤面全体に合わせた初期視点、選択／合法地点／予定地点の枠と文字、ドラッグ中のゴーストを追加しました。

Step 15では戦場内の大きな結果カードに勝敗・終局理由・最後の手と「新しい対局／戦史再現／結果を保存」を表示し、終局時と終局済みの再開時には結果へスクロールします。直前の手は自軍／CPU、出発→到着、公開できる駒名、使用列を文章と矢印・発／着の輪で表示します。除去された自軍駒も初期配置と公開棋譜から名前を確認でき、対局中のCPU駒名は不明のままです。金の六角台座＝将官、銀の丸台座＝佐官、水色の角台座＝尉官に3／2／1の印を重ね、翼・馬・工具・フード・旗も大きくしました。短い「駒の見分け方」を折りたたんで確認できます。

Step 16では勝利＝金の勝鬨、敗北＝落ち着いた藍、引き分け＝中立の青緑として結果を区別します。人間勝利時は短い紙吹雪を戦場に重ね、OSの「動きを減らす」設定では省略します。勝利済み対局を開いた時にも一度だけ祝福し、約4秒で終了します。戦史再現は専用の鑑賞画面に拡張し、駒の移動・発着の軌跡と、正式棋譜に基づく開戦／初接触／突破／本陣圧迫／重要駒撃破／終局の解説を組み合わせます。「見どころ」から局面を選べ、最終手からは最初から再生できます。高速再生でも戦闘演出を見切らない最低表示時間を確保します。これは鑑賞モードであり、描画性能の測定機能ではありません。ルール、CPU、保存・暗号化形式、BGMと効果音の設定は変更していません。

初期配置から終局まで、通常利用では二次元盤面を表示しません（Step 12B）。配置では自軍23枚の立体キャラクターを選び、金枠の交換先を押すと既存の配置検証を通して交換・自動保存します。8種類の「陣形を変更」も利用できます。「全景」「真上」「自軍正面」「敵軍正面」「選択中の駒」「直前の手を追う」は配置・対局で共通です（選択／着手がない視点は無効）。Three.jsは配置または保存対局を開く時に読み込み、WebGL2非対応・読込失敗・コンテキスト喪失時だけ既存Boardへ切り替えます。開発用配置画面は二次元のまま残します。ルール判定は既存処理のままで、描画器は地点と列の選択だけを通知します。

BGMは初期OFFです。上部のBGMボタンを押すと初めて音源を読み込みます。ON/OFF・音量は対局保存と別のLocalStorage設定に保存し、ONを保存済みでもページ再読み込み後は「BGM 再生」を押すまで無音です。

Step 13では木製の将棋駒型台座、種類別装備、墨線と本陣のある軍議盤を採用しました。「AI参謀」をONにすると、最大3件の自軍合法手、CPUの着手理由の公開要素、未知敵駒の候補と根拠を表示します。生成AIモデルではなく、公開情報だけを使うゲーム内の戦術解析エンジンです。助言を自動実行せず、敵の真の種類や確率・勝率を表示しません。CPU説明では種類に依存する秘密の点数と総合点を隠し、「公開要素小計」と表示します。

戦闘時には800 msの墨・光粒子と短いカメラ演出を表示し、直近の手動視点操作とOSの演出低減設定を尊重します。上部の「効果音」は初期OFFで、明示操作後に軽量な合成音を鳴らします。終局後の「戦史再現」では初期配置と正式棋譜から局面を再構築し、再生・停止・前後・手数指定・0.5/1/2倍速を利用できます。元の保存対局は変更しません。

描画はWebGPUを優先し、初期化・デバイス喪失時は既存のWebGL2描画へ切り替えます。両方の三次元描画を利用できない場合だけ二次元を使用します。今回のChromium検証環境ではWebGPUデバイス作成が`dxil.dll`エラーで失敗したため、実WebGPU描画は未検証です。WebGL2とGPU成功／失敗分岐の自動試験を別に記録しています。実機の描画性能・音の聴感は追加確認が必要です。

対CPU戦ではCPUの思考へ渡す情報からプレイヤーの未公開駒種類を除外します。プレイヤー側画面でも対局中のCPU駒種を伏せます。ブラウザ内には対局を処理する完全盤面があるため、これはオンライン対人戦の秘密保護や改ざん耐性の実証ではありません。架空の配置を使う開発用検証画面も残します。

配置中の難易度・乱数種・自軍配置と、確定済みの対CPU戦はブラウザ内へ自動保存され、再読み込み後に「続きから」再開できます。長期保管・端末変更には「対局を保存」でパスワード付き`.mcsave`ファイルを作り、移行先の「保存した対局を読み込む」を使います。パスワードは保存されないため、忘れるとファイルを復元できません。ブラウザの保存領域を消去すると自動保存も失われるので、必要な対局はファイルで保管してください。別の端末やURLの保存領域とは共有されません。Supabase、DB、認証、招待、サーバー処理、オンライン対戦、通知は未実装です。

## テストプレイ公開

GitHub Pagesの公開先は [テストプレイ版](https://dicek9750.github.io/military-chess-online/)です。mainへのpushで `.github/workflows/deploy-pages.yml` が本番用ビルドを作り、Pagesへデプロイします。公開元はGitHub Actionsです。各版の反映はデプロイ結果と公開ページで確認してください。開発サーバーは従来どおり `/` で動き、公開ビルドは `/military-chess-online/` を基準パスにします。

## 開発と検証

Node.js 22.12以上とnpmを使用します。依存版はpackage-lock.jsonで固定します（確認環境：Node 24.19.0 / npm 12.0.2）。

```sh
npm ci
npx playwright install chromium
npm run dev
```

開発サーバーはlocalhost限定です。トップ画面の「コンピューターと対戦」から難易度を選び、自軍23枚の配置を交換・確定すると対局を開始します。駒と金枠の移動先を選び、着手内容を確認して実行します。直前の着手は盤面と文章で確認でき、全履歴は折りたためます。「続きから」は有効な自動保存がある場合だけ使えます。既存の対局や配置下書きを新しい対局で置き換える前には確認を表示します。開発用ローカル対局はトップ画面の「開発用・将来の機能」内に分離しています。

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
# 上記すべてを順に実行
npm run check
```

`npm run test:watch`は単体テストの監視、`npm run preview`はビルド成果物のローカル確認です。PlaywrightはChromiumでモバイル・PCの操作と320/360/390/430/768/1280px幅を確認します。実スマートフォンの指操作・実機検証は第6段階で行います。

- `src/game/`：ネットワーク・DB・React・ブラウザに依存しない盤面、配置、移動、戦闘、終局計算。入力を変更せず新状態を返します。
- `src/cpu/`：CPU専用の閲覧情報変換、難易度別の手選択、合法配置、共通ルールを使うCPU手番。思考関数は完全盤面を受け取りません。
- `src/intelligence/`：公開情報による戦術候補・CPU理由・未知敵候補と、終局後だけ許可する正式棋譜再構築。
- `src/ui/`：配置・盤面・着手確認・終局表示。正式ルールの再定義はしません。
- `src/battlefield3d/`：安全な表示状態への変換、常時表示、地点・列の入力通知、短い移動演出。ゲームロジックを持たない正式な対局操作面です。
- `src/dev/`：架空の初期配置・検証盤面と、用途別の配置下書きアダプター。対CPUの自軍配置下書きにも利用します。
- `src/**/*.test.*` / `tests/`：Vitest・React Testing LibraryとPlaywright。225組の戦闘期待値はGAME_RULES.mdから読み取ります。

対CPU戦の準備中データ（難易度・乱数種・配置）と、確定済み対局の全状態は別のLocalStorageキーへ保存します。配置確定・先手抽選・CPU配置生成は1つの整合した開始状態として保存します。人間・CPUの着手、付随する自動PASS、終局も確定後に保存します。保存の破損や未対応版は復元せず、新規対局・ファイル読み込みを選べます。開発用の検証対局は従来どおり永続化しません。`client_move_id`・`state_version`によるオンライン通信制御は将来の対人戦拡張で扱います。

## Step 17：軍議操作・勝鬨・戦史映画

通常経路は三次元パネル内の「軍議操作」で配置確定、陣形管理、着手確認、保存、AI参謀、終局・映画の操作を行います。盤面を縮小しないため、操作欄や詳しい解説は縦スクロールで利用します。カメラは固定ボタンのみです。BGM・効果音は既存の単一コントローラーを上部に残し、「音の設定」から移動できます。

自作陣形は名前（1〜40文字）、お気に入り、日時、自軍23地点の種類だけを対局とは別に保存し、最大24件を管理します。読込時は新しい内部IDを発行し、正本の配置検証を通ったものだけ適用します。破損・容量不足で現在の配置は失いません。標準8陣形は引き続き利用できます。

「戦場設定」には自動／高品質／標準／軽量と戦況レイヤーがあります。自動は初期化時の画面・DPR・公開メモリー情報で一度選びます。戦況は敵の接近位置、突破口、公開経路を示し、敵の真の攻撃範囲や勝率を表示しません。階級ごとの旗・双角・飾りと、合法経路・ホバー・ドラッグ中の「移／禁止／確定」を追加しています。

新たな人間勝利は正式な最終着手の表示だけを1.2秒へ延ばし、勝鬨、光の輪、花びら・紙吹雪、2〜4門の抽象祝砲で祝います。保存状態・棋譜は巻き戻しません。効果音ON時だけ合成ファンファーレと祝砲音を鳴らし、既存BGMを2.6秒だけダッキングします。再開した終局と映画から戻った勝利は短縮し、動きを減らす設定では静的結果中心です。

終局後の「戦史再現」は **CINEMATIC CHRONICLE / 戦史映画**。通常の将棋駒・格子ではなく、土・草・街道・橋・陣幕と指揮官＋護衛の部隊を描画します。正式棋譜の移動、戦闘結果、除去だけを行軍・接触・退場として再現します。事実解説・実際に発生した章・速度・停止・前後・スライダーを保持し、鑑賞中に対局保存を変更しません。「名場面を保存」は戦場と手数・場面・結果をPNGへ合成。「名場面を共有」はファイル共有対応環境で共有し、それ以外はPNG保存へ進みます。画像にURL・個人情報・内部IDを付加しません。

映画・PNG合成は別の遅延チャンクです。静止部隊はInstancedMeshで描画をまとめ、連続描画は短い演出中だけです。実WebGPU・実スマートフォンの発熱・音の聴感は、ChromiumのWebGL2自動検証とは区別します。

# military-chess-online
Military chess strategy game: CPU play first, online multiplayer planned

日本の軍人将棋を基礎とする、スマートフォン優先の不完全情報型戦略ゲームです。**初回公開は1人用の対CPU戦**を目標とします。オンライン2人対戦は将来拡張として設計を保持します。

## 現状

対CPU戦、保存機能、スマートフォン向け配置・着手・履歴・結果表示を備えています。友人向けのテストプレイ版として公開を進めています。正式ルールはv0.2です。飛行機は前後移動で途中の敵味方駒を飛び越えます。保存形式と暗号化方式は変更していません。

初期配置は盤面、対局中は三次元戦場と操作補助UIを中央に置き、十分な幅と高さがあれば左右にルールを並べます。1画面に収まらない画面ではルール欄を隠し、既存の「遊び方」から確認できます。

対局画面の正式な主操作面は三次元戦場です（Step 12）。自作低ポリゴン兵士と常時名称ラベルを表示し、敵は終局まで共通の「？」兵士に統一します。自軍→金枠の移動先→同じ目的地を再タップ、または補助UIの「確定して実行」で着手します。HQ間飛行機ではC/D経路を先に選びます。選択解除・直前の着手／戦闘・履歴・終局後公開・保存再開も利用できます。ドラッグで回転、2本指／ホイールで拡大縮小、「視点を戻す」で自軍側からの全景に戻ります。

初期配置から終局まで、通常利用では二次元盤面を表示しません（Step 12B）。配置では自軍23枚の立体キャラクターを選び、金枠の交換先を押すと既存の配置検証を通して交換・自動保存します。8種類の「陣形を変更」も利用できます。「全景」「真上」「自軍正面」「選択中の駒」は配置・対局で共通です。Three.jsは配置または保存対局を開く時に読み込み、WebGL2非対応・読込失敗・コンテキスト喪失時だけ既存Boardへ切り替えます。開発用配置画面は二次元のまま残します。ルール判定は既存処理のままで、描画器は地点と列の選択だけを通知します。

BGMは初期OFFです。上部のBGMボタンを押すと初めて音源を読み込みます。ON/OFF・音量は対局保存と別のLocalStorage設定に保存し、ONを保存済みでもページ再読み込み後は「BGM 再生」を押すまで無音です。

対CPU戦ではCPUの思考へ渡す情報からプレイヤーの未公開駒種類を除外します。プレイヤー側画面でも対局中のCPU駒種を伏せます。ブラウザ内には対局を処理する完全盤面があるため、これはオンライン対人戦の秘密保護や改ざん耐性の実証ではありません。架空の配置を使う開発用検証画面も残します。

配置中の難易度・乱数種・自軍配置と、確定済みの対CPU戦はブラウザ内へ自動保存され、再読み込み後に「続きから」再開できます。長期保管・端末変更には「対局を保存」でパスワード付き`.mcsave`ファイルを作り、移行先の「保存した対局を読み込む」を使います。パスワードは保存されないため、忘れるとファイルを復元できません。ブラウザの保存領域を消去すると自動保存も失われるので、必要な対局はファイルで保管してください。別の端末やURLの保存領域とは共有されません。Supabase、DB、認証、招待、サーバー処理、オンライン対戦、通知は未実装です。

## テストプレイ公開

GitHub Pagesの公開先は `https://dicek9750.github.io/military-chess-online/` を想定しています。mainへのpushで `.github/workflows/deploy-pages.yml` が本番用ビルドを作り、Pagesへデプロイします。利用にはリポジトリのPages設定でGitHub Actionsを公開元にする必要があります。実際の公開可否・URLの有効性はGitHub Pagesの設定とデプロイ結果で確認してください。開発サーバーは従来どおり `/` で動き、公開ビルドは `/military-chess-online/` を基準パスにします。

## 開発と検証

Node.js 22.12以上とnpmを使用します。依存版はpackage-lock.jsonで固定します（確認環境：Node 24.19.0 / npm 12.0.2）。

```sh
npm ci
npx playwright install chromium
npm run dev
```

開発サーバーはlocalhost限定です。トップ画面の「コンピューターと対戦」から難易度を選び、自軍23枚の配置を交換・確定すると対局を開始します。駒と金枠の移動先を選び、着手内容を確認して実行します。直前の着手は盤面と文章で確認でき、全履歴は折りたためます。「続きから」は有効な自動保存がある場合だけ使えます。既存の対局や配置下書きを新しい対局で置き換える前には確認を表示します。開発用ローカル対局はトップ画面の「開発用・将来の機能」内に分離しています。

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
# 上記すべてを順に実行
npm run check
```

`npm run test:watch`は単体テストの監視、`npm run preview`はビルド成果物のローカル確認です。PlaywrightはChromiumでモバイル・PCの操作と320/360/390/430/768/1280px幅を確認します。実スマートフォンの指操作・実機検証は第6段階で行います。

- `src/game/`：ネットワーク・DB・React・ブラウザに依存しない盤面、配置、移動、戦闘、終局計算。入力を変更せず新状態を返します。
- `src/cpu/`：CPU専用の閲覧情報変換、難易度別の手選択、合法配置、共通ルールを使うCPU手番。思考関数は完全盤面を受け取りません。
- `src/ui/`：配置・盤面・着手確認・終局表示。正式ルールの再定義はしません。
- `src/battlefield3d/`：安全な表示状態への変換、常時表示、地点・列の入力通知、短い移動演出。ゲームロジックを持たない正式な対局操作面です。
- `src/dev/`：架空の初期配置・検証盤面と、用途別の配置下書きアダプター。対CPUの自軍配置下書きにも利用します。
- `src/**/*.test.*` / `tests/`：Vitest・React Testing LibraryとPlaywright。225組の戦闘期待値はGAME_RULES.mdから読み取ります。

対CPU戦の準備中データ（難易度・乱数種・配置）と、確定済み対局の全状態は別のLocalStorageキーへ保存します。配置確定・先手抽選・CPU配置生成は1つの整合した開始状態として保存します。人間・CPUの着手、付随する自動PASS、終局も確定後に保存します。保存の破損や未対応版は復元せず、新規対局・ファイル読み込みを選べます。開発用の検証対局は従来どおり永続化しません。`client_move_id`・`state_version`によるオンライン通信制御は将来の対人戦拡張で扱います。

## 仕様の基準

- [ゲームルール](docs/GAME_RULES.md)：正規座標・論理地点・駒・勝敗表・終局・U1〜U5の決定記録・R1。
- [アーキテクチャ](docs/ARCHITECTURE.md)：対CPU戦の構成と、将来のオンライン対人戦設計。
- [セキュリティ](docs/SECURITY.md)：対CPU戦の公平性と将来のオンライン秘密保護。
- [保存データ設計](docs/DATA_MODEL.md)：ローカル保存形式と将来のDB設計。
- [サーバー処理設計](docs/SERVER_LOGIC.md)：現在のCPU手番と将来のサーバー処理。
- [プレイヤー操作の流れ](docs/USER_FLOW.md)：承認済みの操作と、将来のオンライン対局・再開。
- [実装計画](docs/IMPLEMENTATION_PLAN.md)：対CPU公開と将来のオンライン拡張の段階別条件・検証・判断事項。

ルールの唯一の基準はGAME_RULES.md、必須の保護要件はSECURITY.mdです。技術候補は確定ルールを変更しません。矛盾は実装で解釈せず文書を修正し、未決定事項を暗黙に確定させません。

初回公開先の第一候補はGitHub Pagesです。対CPU戦はブラウザ内で処理します。将来のオンライン対人戦ではSupabaseをバックエンド候補、メールMagic Linkをログイン第一方式とし、敵秘密情報をサーバー側で分離します。

オンライン対人戦拡張では `client_move_id` による再送冪等化、単調増加する `state_version`、作成時固定の `ruleset_version` を正式方針とします。

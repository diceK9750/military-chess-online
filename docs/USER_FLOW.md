# プレイヤー操作の流れ

スマートフォン縦持ちを中心にした対CPU戦の流れと、将来のオンライン対人戦操作を記載する。ゲームの意味は[GAME_RULES.md](GAME_RULES.md)、将来のオンライン公開範囲は[SECURITY.md](SECURITY.md)に従う。保存は[DATA_MODEL.md](DATA_MODEL.md)、処理は[SERVER_LOGIC.md](SERVER_LOGIC.md)、実装順は[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)を参照する。

初回公開は1人用対CPU戦を目標とする。オンライン対人戦に関するX1〜X5の承認済み方針は将来拡張として保持し、参加待ち中の配置開始時期やX6の保存・削除運用は未決定。現在は第4段階のローカル保存・暗号化ファイルまで進み、認証・外部送信・オンライン保存は行わない。

## 初回公開目標：対CPU戦

タイトルの「CPUと対戦」から「かんたん／ふつう」を選び、利用者がPlayer 1として23枚を配置する。CPUはPlayer 2の合法な23枚配置を自動生成する。利用者が「この配置で確定」を押した後に先手を抽選し、対局を始める。配置中の難易度・乱数種・自軍配置をブラウザへ保存するため、再読込後の「続きから」で配置へ戻れる。確定後は整合した開始状態を対局保存へ記録する。

利用者は自軍駒→合法移動先→着手内容確認→確定の順で進む。CPU手番なら入力を止め、CPUの閲覧可能情報だけで手を選び、人間と同じルール処理で移動・戦闘・終局を確定する。対局中、利用者画面のCPU駒種は不明駒として表示する。CPU思考には利用者の未公開駒種を渡さない。終局では勝者・引き分けと理由を表示する。

人間・CPUの各着手、付随する自動PASS、終局を確定した後に対局状態を自動保存する。タイトルの「続きから」は有効な保存がある場合だけ使える。保存値の破損・未対応版ではエラーを示すが、新規対局とファイル読み込みは続けられる。進行中の対局を新しい対局で置き換える前には保存・開始・キャンセルを選べる確認を表示する。

対局画面の「対局を保存」ではパスワードを2回入力し、8文字以上かつ一致を確認して`.mcsave`ファイルを作る。終局済みでも保存できる。タイトルの「保存した対局を読み込む」ではファイルとパスワードを指定する。復号・形式版・ルール版・全局面の検証に成功してから復元し、既存対局があれば置換確認を行う。失敗時は元の保存を変更しない。パスワードは保存せず、入力中に表示・非表示を切り替えられる。第5段階で縦持ち操作・視認性を完成し、第6段階でGitHub Pages公開と実機確認を行う。

## 将来のオンライン対人戦操作

以下の既存設計は第7段階以降に使用する。オンライン対人戦では別端末・長期不在からの再開、サーバーによる相手秘密の分離を維持する。

### 1. 初回利用とログイン

1. ゲームを開く。
2. ログインして本人の対局へアクセスする。
3. 対局一覧を開き、対局がなければ新規作成へ進む。

電子メールに届くMagic Linkを正式ログインの第一方式として承認済み（X1）。Supabase Authを候補サービスとする。メールを入力し、届いたリンクを開いて元の対局または招待先へ戻る流れを推奨する。端末変更時にも同じアカウントを使う。メール未着・リンク期限切れの具体的な再送表示は後工程で設計する。認証リンクの期限をゲームの手番期限として扱わない。今回はログインを実装しない。

対局一覧には相手、参加待ち／配置中／自分の手番／相手の手番／終了、直近の出来事を簡潔に表示する案。長期不在に「期限切れ」の表示を付けない。オンライン状態や相手の最終利用時刻を必要条件にしない。

### 2. 新しい対局と招待

作成者が「新しい対局」を押す→対局が作られる→招待リンクが表示される→本人がLINE等で友人へ送る→参加を待つ。招待の共有先・送信は利用者自身が選ぶ。アプリが連絡先を取得したり自動で他人へ送ったりする機能をオンライン対人戦の初版へ追加しない。

作成者をPlayer 1、招待参加者をPlayer 2とすることは承認済み（X2）。両者参加後に配置を始めるか、参加待ち中も配置可能にするかは引き続き未決定。P1が先手とは限らず、先手は双方の配置確定後にサーバーが抽選する。自陣はどちらのプレイヤーも画面下側に表示する。

招待された友人はリンクを開く→必要ならログイン→参加する対局を確認→参加→初期配置へ進む。参加確認の表示方法はX3。自分自身を相手枠へ登録できず、既参加者が同じリンクを開いたら既存対局へ戻る。使用済み・無効なリンクで非参加者へ盤面を見せない。無効なら作成者にリンクの確認を依頼する案。

招待は固定有効期限なし、認証済み利用者のみ参加可、参加完了後は再利用不可とする（X3・承認済み）。作成者は参加前に無効化でき、再発行時は古い招待を無効化する。参加後はリンクを保存していなくても対局一覧から再開できる。実際の招待機能は今回は作らない。

### 3. 初期配置

1. 自分の23枚を見て自陣23地点へ配置する。敵の種類・配置途中は見えない。
2. タップで駒と置き場所を選ぶ。配置済み駒の交換も少ない操作で行えるようにする案（X4）。
3. 未配置枚数と配置エラーをその場で確認する。地雷・軍旗の入口配置禁止、軍旗の最後列禁止を本人に説明する。HQは2マス幅でも1枚だけ置ける。
4. 配置途中は自動保存する（X4・承認済み）。正式実装では「保存中／保存済み／再試行」を表示し、保存・確定をサーバーでも検証する。
5. 23枚が正しくそろったら「この配置で確定」を押す。正式実装では相手が未確定なら待機し、ブラウザを閉じてもよい。
6. まだ対局未開始なら「確定を解除して編集」を使える。双方確定したら自動的に配置が固定され先手を決め、対局が始まる。

配置は自由に編集できるが、READY中の直接編集は行わず解除を先に行う。解除操作と開始が同時になりサーバー側ですでに開始していれば、解除せず開始後の盤面を表示する。相手の秘密配置は返さない。配置・確定に現実時間の期限はない。

自動保存と明示的な配置確定をオンライン対人戦でも採用する。オンラインの再開はブラウザだけに下書きを残す設計に依存しない。現在の対CPU画面は配置下書き・準備中状態・確定済み対局を別のブラウザキーへ保存する。オンラインのREADY・サーバー保存とは分離する。オンライン保存中・失敗時の細かな表示は後工程で設計する。

### 4. 対局を開いたとき

最初に「自分の手番／相手の手番／終了」を大きく示す。次に最新盤面、前回の着手、前回の戦闘結果、自動的に手番が送られた場合はその説明を示す。対局開始からの履歴へ少ない操作で移れるようにする。

自軍は種類を表示し、敵軍は不明駒として表示する。自分の除去駒は種類を確認できるが、相手の除去駒は種類を表示しない。数か月ぶりでも前回の移動元・移動先と除去された側から状況を追えるようにする。戦闘後も対局が続くなら相手種類の名称・画像・説明を表示しない。

画面は原則横スクロールなし、タップ対象を小さくしすぎず、自軍と敵軍は色だけに頼らず向きや枠でも区別する。PCでも同じルール・公開範囲を使う。

### 5. 自分の手番

1. 自軍駒を選ぶ。
2. 移動できる場所を表示する。判定中・状態が古い場合は送信を確定させない。
3. 移動先を選ぶ。
4. 飛行機が両司令部間を移動する場合はC列かD列を選ぶ。片方だけ合法ならその列だけを選択可能にする。両方不合法なら移動先として確定できない。
5. 移動先と経路を確認して「この手を送る」を押す。
6. 送信中と表示し、同じ操作を重ねて送らない。
7. サーバーの確定結果を受け取って盤面と履歴を更新する。
8. 相手の手番、相手の自動PASSによる再び自分の手番、または終局を表示する。

駒選択→合法移動先表示→移動先選択→確認→確定実行を正式採用する（X4）。現在は同じ画面内の確認欄で実装する。送信前は駒・移動先・C/Dを選び直せる。両列合法なら利用者にC/Dを選択させ、片列だけ合法なら確認欄に明示して自動選択してよい。両列不合法なら移動不可。勝手な列差し替えはしない。確定済み着手を取り消す機能は追加しない。

利用者には「C側の縦経路／D側の縦経路」と盤面上の線を対応させる案。P2の表示が180度回転しても、保存される正規C/Dの意味は変えない。仮想アンカーや状態版番号など内部実装用語を基本操作へ持ち込まない。

移動先表示は戦闘で勝てる場所の予測ではない。敵種類を取得して画面内で勝敗を予測しない。飛行機の敵HQ停止だけでは勝利にならず、司令部占領資格は既存ルールどおり。

### 6. 相手の手番と自動的な手番送り

相手の手番中も盤面・許可された履歴を見られるが、着手は送れない。ブラウザを閉じて待てる。次に開いたときや更新操作で最新状態を取得する。相手への催促や通知はオンライン対人戦の初版必須にしない。

合法手がない場合はサーバーが自動で手番を送るため、利用者がパスを選ぶ必要はない。「動かせる手がないため手番が移りました」と棋譜に残す。自動送りは戦闘なし50手に数えず、両者とも動けなければ引き分けとなる。任意のパス操作は提供しない。

自分用の敵駒推理メモは将来追加可能。オンライン対人戦の初版の進行には必要とせず、追加する場合は本人だけに保存・表示する設計を別途行う。推理内容を本当の敵種類として扱わない。

### 7. 長期中断・端末変更後の再開

再ログイン→対局一覧→対局選択→最新盤面と履歴を取得→現在の手番から続ける。元端末や同じブラウザの一時保存は必須でない。数日・数週間・数か月の不在で自動敗北・引き分け・削除にしない。

別端末で先に操作されていた場合は、その最新結果を表示し、古い選択は破棄して選び直す。表示する相手・自分の情報は、ログインしたアカウントに応じて再取得する。アカウント切替で前の盤面・秘密情報を残さない。

### 8. 通信が切れたとき

送信失敗を即座に「未実行」と表示しない。応答だけ失った可能性があるため「結果を確認しています」と表示し、追加の着手は結果確認まで抑止する。送信中表示や確認動線の具体形はX4。

再接続時には同じ着手の識別情報でサーバーへ結果を確認する。成功済みならその結果と最新盤面を表示し、未処理なら同じ内容を同じ識別情報で再試行できる。別の経路・移動先へ変えた要求を「同じ着手の再送」として送らない。

再読み込みや端末変更で手元の識別情報を失っていても、サーバーの最新状態と本人の直近着手を読み、実行済みかを確認できるようにする。不明なまま新しい要求として古い手を自動再送しない。着手がまだ処理中でも同じ版の二重受理はサーバーが防ぐ。古い画面の場合は「盤面が更新されました」と案内して最新状態へ戻す。

### 9. 終局

勝利・敗北・引き分けと、司令部占領、占領可能駒の除去、双方合法手なし、戦闘なし50手など確定した理由を表示する。双方の占領可能駒が同時に0になった場合も引き分け理由を示す。終局後は新しい手を送れない。

サーバーが終局と参加者権限を確認した後、双方の参加者が全駒種類・LOCK時初期配置・完全な履歴・各戦闘の双方の種類を確認できる。表示側で先に秘密を受信して待機させる方式にはしない。第三者や未ログイン者へ公開する機能は追加しない。

オンライン対人戦の初版は初期配置と順序付きの完全棋譜を読めることを完了条件とする。将来の対局再生では保存した移動経路・C/D列とルール版を使い、別の列を推測しない。再生アニメーションは第11段階の任意機能。

### 10. 表示名の正式方針と保存運用の未承認案

表示名は任意で、未設定でも利用可能（X5・承認済み）。未設定時は本人側「あなた」、相手側「対戦相手」を基本とする。プロフィール編集の拡張は後工程とする。メールアドレスを対戦相手の表示名として露出しない。

対局を一覧で非表示にすることと、共有の正本を削除・終局することを混同しない。放棄・削除・退会の利用者向け操作はX6で設計承認するまで提供しない。期限や自動削除を既定の体験に追加しない。
